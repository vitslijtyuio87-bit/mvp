Auth System (MVP) - мінімальний життєздатний проєкт
Локальний консольний застосунок реєстрації та автентифікації на Python. Лише стандартна бібліотека, без зовнішніх залежностей.

Можливості

Реєстрація: ім'я, вік, логін, пароль, 4 секретні питання
Вхід: пароль + відповіді на всі 4 питання
Приховане введення секретів (getpass)
Блокування акаунта після 5 невдалих спроб (зростає: 1 хв, 2 хв, 4 хв, … до 24 год)
Дані зберігаються в локальному JSON-файлі
Безпека

Хешування: scrypt (N=2^17, r=8, p=1) з унікальною сіллю для кожного секрету
Паролі й відповіді не зберігаються у відкритому вигляді
Порівняння хешів за постійний час (hmac.compare_digest)
Однакове повідомлення про помилку для будь-якої причини невдачі
Фіктивне хешування для неіснуючих логінів і мінімальний час відповіді (захист від user enumeration за часом)
Спроба входу списується до перевірки секретів, тому паралельні процеси не обходять ліміт
Міжпроцесне блокування БД через flock (Linux/macOS) / msvcrt (Windows), яке звільняється разом із процесом
Атомарний запис БД (tmp → fsync → os.replace)
Allow-list параметрів scrypt: файл БД не може задати довільні значення пам'яті
Валідація структури БД при читанні
Нормалізація Unicode (NFKC) і різних апострофів
Автоматичне оновлення хешів зі старими параметрами після успішного входу
Вимоги

Python 3.10+
термінал ( IDE без TTY, як-от IDLE чи деякі консолі PyCharm, програма відмовиться вводити секрети)
Запуск

python auth_system.py
Меню:

Реєстрація
Вхід
Вихід
Вимоги до введених даних

Ім'я: літери, дефіс, апостроф, до 50 символів
Вік: 1–120
Логін: a-z, 0-9, _, 3–32 символи
Пароль: мінімум 12 символів, не збігається з логіном і поширеними паролями, не збігається з відповідями на питання
Відповіді: не порожні (регістр і зайві пробіли не враховуються)
Обмеження( аналіз коду за допомогою ШІ та думка спеціалістів )

Секретні питання не є другим фактором. Відповіді можна вгадати або знайти у відкритих джерелах(osint)
Немає мережевого рівня, TLS і серверного rate limiting. Захист від перебору діє лише в межах цієї програми
Блокування можна використати для DoS: будь-хто, хто може запустити програму, здатен заблокувати чужий логін
Хто має доступ до файлів або коду, обходить усі перевірки, а єдиний реальний захист у цьому разі дає стійкість хешів
JSON-файл не масштабується: кожна зміна перезаписує файл цілком
Немає відновлення пароля, зміни пароля й видалення акаунта
Захист від аналізу часу відповіді наближений, а не гарантований
